# 企業級 API v2.4 資安架構與 Token 升級轉移準則

本準則規範企業核心系統由舊有 Session 機制過渡至 OAuth 2.1 / OIDC 統一身份驗證體系之技術標準。所有相依微服務組件與外部介接方必須於 2026 年第四季前完成改裝升級。

### 一、 核心架構調整清單
- **認證體系升級**：全面汰除靜態 API Key 與缺乏非對稱簽章之 Basic 認證，強制採用基於 RFC 9068 的 JWT 結構化存取權杖（Access Token）。
- **金鑰輪更機制**：授權伺服器統一透過 JWKS（JSON Web Key Set）端點發布公鑰，並落實 72 小時自動輪更流程。
- **權限模型限縮**：廢止粗放式角色分配，嚴格遵循最小權限原則（PoLP），改採 Scope 與細粒度屬性宣告。

### 二、 Token 存活週期與防護標準
1. **Access Token**：
   - 有效時限：上限 15 分鐘（900 秒），逾時必須無條件阻絕。
   - 簽署演算法：僅許可採用 `RS256`、`ES256` 或 `EdDSA`，嚴禁接受 `none` 演算法與對稱金鑰。
2. **Refresh Token**：
   - 採用單次使用輪替機制（Token Rotation with Revocation）。
   - 當偵測到已被註記作廢之 Refresh Token 再次發起請求時，系統將觸發全帳戶會話撤銷。

### 三、 工程團隊遷移驗證檢查表
- [ ] 各服務閘道（API Gateway）已啟用 JWKS 公鑰快取與背景非同步更新機制。
- [ ] 所有對外請求之 Header 均包含唯一關聯追蹤識別碼（`X-Correlation-ID`）與追蹤旗標。
- [ ] 服務日誌中已完全過濾並隱匿 Authorization Header、Token 內容與敏感隱私個資（PII）。
- [ ] 完成混沌工程實測：驗證授權伺服器斷線 5 分鐘內，本地快取公鑰仍可正常放行合法請求。
