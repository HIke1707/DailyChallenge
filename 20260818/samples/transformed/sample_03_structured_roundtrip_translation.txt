# 企業 API v2.4 安全架構與 Token 移轉指南

本文件定義了企業主要服務從舊的 Session 架構過渡到 OAuth 2.1 / OIDC 身份驗證架構的技術規範。所有內部微服務和外部合作夥伴必須在 2026 年 Q4 之前完成整合。

### 1. 主要架構變更
- **認證機制升級**：淘汰靜態 API 密鑰和 Basic Auth，全面改用符合 RFC 9068 的 JWT 結構化存取權杖。
- **金鑰輪換**：授權伺服器透過 JWKS 端點分發公鑰，並執行 72 小時自動定期更換。
- **權限限縮**：取消寬鬆角色分配，遵循最小權限原則，改用 Scope 進行精細控制。

### 2. Token 安全限制
- **Access Token**：最長有效期 15 分鐘（900 秒），僅接受 RS256/ES256/EdDSA 簽章，禁止使用 none 演算法。
- **Refresh Token**：強制單次使用輪換機制。一旦檢測到重放已撤銷的 Token，將立即封鎖該帳戶所有會話。

### 3. 上線查核清單
- [ ] API 閘道已啟用 JWKS 公鑰本地快取機制。
- [ ] 所有請求標頭均包含唯一追蹤 ID（`X-Correlation-ID`）。
- [ ] 應用程式日誌已徹底過濾所有 Token 和個人隱私數據（PII）。
- [ ] 通過容錯測試：在認證伺服器故障 5 分鐘內，本地快取仍可驗證合法請求。
