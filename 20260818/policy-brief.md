# 企業內容治理政策簡報：AI 內容來源標記與水印訊號解讀指南 (Policy Brief)

**文件版本**：v2.0 (2026 年 8 月 18 日)  
**適用對象**：企業資訊長 (CIO)、資安長 (CISO)、法遵長 (Chief Compliance Officer)、內容審查與生成式 AI 治理委員會  
**核心主旨**：如何正確解讀 Anthropic Claude 等新一代 AI 統計文字水印與 C2PA 來源標記，避免將弱訊號或文字修改指標誤判為硬性合規依據。

---

## 執行摘要 (Executive Summary)

Anthropic 於 2026 年 8 月公開說明 Claude 統計式文字水印機制，引發企業界高度關注。然而，依據本專案之**驗證能力前置盤點（Preflight）**，Anthropic 官方目前**並未釋出**公開的文字水印解密 API 或本機檢驗套件；因此在當前環境下，文字水印狀態應忠實判定為 `not_verifiable_in_environment`。

本次實驗透過對 4 組代表性文字進行 9 種受控變換操作（共 36 筆測試樣本），**精確量測了不同編輯操作所造成的客觀文字修改幅度（編輯距離、序列相似度、詞彙交集率與雜湊變更）**。結合統計水印之理論架構，本簡報為企業管理層提供嚴謹、不誇大證據的內容治理與審計軌跡建置指引。

---

## 一、 核心問題解答與證據等級判定

### 1. 哪些 Provenance 訊號只能作為「輔助訊號」？
- `[Observed]` **文字修改幅度指標（Diff / Edit Distance / Similarity）**：
  - 實驗實測量測到的 Levenshtein 編輯距離、SequenceMatcher 比率與 Jaccard 詞彙交集率，僅能代表「文字字面被修改了多少」，**絕對不可直接等同於「水印訊號強弱」**。
- `[Observed]` **第三方 AI 偵測器分數**：
  - 坊間基於語言模型困惑度（Perplexity）之第三方偵測器無法獲取 Anthropic 專屬密鑰，誤判率顯著，不可作為官方水印存在之證明。
- `[Supported inference]` **輔助訊號定位**：
  - 任何來源標記或統計訊號均應定位為**「分流標記（Triage Indicator）」**，用於觸發內部人工複核，嚴禁作為自動化裁決之唯一依據。

### 2. 哪些情境「絕對不能」用來做硬性 AI 判定？
- `[Supported inference]` **經過同義詞替換與語法修訂的內容**：
  - 根據統計綠名單理論（如 Kirchenbauer 等機制），Token 選擇取決於前驅詞彙之雜湊值。當文字發生 10%~20% 之同義詞替換時（實測詞彙交集率降至 0.70~0.88），將造成前驅雜湊鏈的連鎖失效（Cascading Hash Failure），極可能使統計顯著性跌破檢定門檻。
- `[Supported inference]` **經歷跨語言往返翻譯（Round-trip Translation）的文字**：
  - 翻譯重構會徹底重置 Token 序列。**「在此情境下檢測不到水印，絕不能推論內容非 AI 產出（Negative Fallacy）」**。
- `[Supported inference]` **經歷多重自動化管線處理的內容**：
  - 經由 CMS 範本重排、文法修正軟體處理或摘要工具之內容，微觀統計特徵均遭受破壞。
- `[Unknown]` **極短文字（< 150 字）之統計檢驗可靠度**：
  - 統計水印需累積足夠長度（通常需數百 Token）方能達到統計顯著（z-score > 4.0）。極短篇幅能否可靠檢驗，目前官方未提供理論數據。

### 3. 企業應建立並保存哪些審計軌跡（Audit Trail）？
因事後被動檢驗存在高脆弱性與檢定工具不可得之限制，企業應建立**「第一方主動審計軌跡 (1st-Party Audit Trail)」**：

| 審計軌跡要件 | 具體內容與技術規格 | 證據等級分類 |
| :--- | :--- | :---: |
| **1. 原始 Prompt 與完整 Raw Output** | 完整封存提示詞、模型版本（如 `claude-3-5-sonnet`）與原始輸出文本。 | `[Observed] 具備操作可行性` |
| **2. 密碼學雜湊與可信時間戳** | 生成時立即計算 SHA-256 雜湊，並附加符合 RFC 3161 之時間戳以防竄改。 | `[Observed] 具備操作可行性` |
| **3. 編修歷程版本追蹤 (Diff Trail)** | 透過版本控制系統（Git/CMS）詳細記錄每次人工修訂之 Levenshtein 與 Token Diff 變更。 | `[Observed] 具備操作可行性` |
| **4. 容器層級 C2PA 數位簽章** | 發布 PDF/圖片檔案時，嵌入包含組織數位證書之 C2PA Manifest。 | `[Supported inference] 具技術標準支援` |
| **5. 驗證狀態如實記錄機制** | 檢驗時若無官方工具，必須誠實記錄 `not_verifiable_in_environment`，嚴禁填入偽造分數。 | `[Observed] 具備操作可行性` |
| **6. 人工複核仲裁制度 (Human-in-the-Loop)** | 建立爭議申訴管道，禁止未經人工審查即依自動化警示對員工或合作夥伴進行懲處。 | `[Supported inference] 具治理必要性` |

## 二、 政策結論宣告總表 (Policy Assertions)

- **[Observed] 客觀事實**：
  1. Anthropic 官方目前未對公眾提供公開之文字水印 Detector API 或 SDK。
  2. 文字在經歷標點、同義詞、段落重排、改寫與往返翻譯後，字面差異與詞彙交集率呈現可精確量化的階梯式變化。
  3. 主流 LLM 對於「如何檢測 Claude 水印」普遍存在幻想不存在 API（如 `anthropic.detect_watermark`）的現象。
- **[Supported inference] 具理論支持之推論**：
  1. 統計式文字水印極度脆弱於局部改寫與翻譯，無法作為防止內容外流或洗稿的強防禦手段。
  2. 未來若官方釋出 Detector，經大幅改寫之文字亦存在極高的偽陰性（False Negative，漏抓）風險。
- **[Unknown] 尚未被證實之未知領域**：
  1. Anthropic 伺服器端內部目前實際設定之綠名單比例 $\gamma$ 與偏差強度 $\delta$ 參數數值。
  2. 官方未來是否會向企業客戶提供以私鑰簽章為基礎之驗證端點。

## 三、 企業行動指引 (Action Items)

1. **修正治理政策中的技術宣稱**：刪除「可透過官方水印 100% 偵測 AI 生成」之條款，修訂為「以第一方 Prompt 與 SHA-256 歷程作為合規佐證」。
2. **防範內部虛假安全機制**：清查企業代碼庫，阻絕任何基於 LLM 幻想端點建構的無效安全驗證邏輯。
3. **推動多模態雙軌標記**：純文字推動版本歷程審計，發布檔案推動 C2PA 容器簽章，構建多層次治理縱深。
